# 视频 AI 五维质检评分规则 V1

状态：讨论确认稿

规则版本：`video_qc_v1`

模型基线：阿里云百炼 `qwen3.7-plus` / `qwen3.7-flash`

最后更新：2026-08-12

## 1. 本版已确认的原则

1. 每个视频按五个维度评分，每维满分 20 分，总分满分 100 分。
2. 拍摄质量、任务质量、库存饱和度和视频相似度全部进入同一套百分制评分，不再建立第二套独立质量分。
3. 每个维度统一采用“`20 × 该维度系数`”计算。
4. 不使用作用于整个总分的质量乘数。某个问题只影响其所属维度。
5. 同一根因不跨维度重复扣分。
6. 硬性否决与百分制分数分开保存。命中硬性否决时仍保留五维原始分，但状态标记为 `hard_reject`。
7. 普通评分视频不设置“低于 60 分不计费”，而是按最终得分进入 `1.0 / 0.8 / 0.6 / 0.4` 四档结算比例；40 分以下仍按 `0.4` 结算。
8. 命中硬性否决时保留五维原始分和有效计费时长，但结算比例强制为 `0`。
9. 模型负责识别事实、片段、证据和建议；规则引擎负责复算分数、有效计费时长和结算结果。
10. 所有分析均在视频上传完成后异步执行，不存在拍摄过程中的实时监测。
11. 所有结果必须记录规则版本、模型版本、调用参数、证据时间点和置信度。

## 2. 总体处理流程

```text
视频上传完成
→ 文件合法性与媒体信息读取
→ 哈希和重复预检
→ 上传后离线画质与手部检测
→ 千问整片低频分析
→ 问题片段加密分析
→ 库存数据库和向量库查询
→ 五维系数计算
→ 硬性否决检查
→ 有效计费片段与无效片段合并
→ 规则引擎复算
→ 匹配结算比例
→ 生成评分、计费、证据和改进建议
```

## 3. 公共定义

### 3.1 分析时长

`T_analysis` 表示可用于评分的媒体时间轴长度。

- 默认等于解析后的实际视频时长。
- 用户上传内容中的等待、黑屏、冻结、模糊、无关内容和低价值片段仍然包含在时间轴内，并由对应维度扣分。
- 只排除平台处理产生的临时片段、容器中不存在的虚假尾时长等非用户内容。

### 3.2 有效计费时长

`T_billable` 表示最终用于结算的视频时长：

```text
T_invalid = 无效片段并集的总时长
T_billable = max(0, T_analysis - T_invalid)
```

所有无效片段必须先裁剪到 `[0, T_analysis]`，再合并重叠区间后计算并集，禁止重复扣除同一段时长。

以下片段计入有效计费时长：

- 与提交任务直接相关、可识别且连续的真实操作；
- 任务过程中的必要等待，如浸泡、加热、设备运行、材料定型；
- 拿取工具、切换步骤等自然衔接；
- 真实的 L0～L3 任务片段。低价值只在第四维扣分，不再从有效时长中剔除。

以下片段不计入有效计费时长：

- 黑屏、严重冻结、损坏或严重不可识别的画面；
- 与提交任务无关的内容；
- 拍摄前后的设备调试、摆放镜头和遗留画面；
- 手部与任务对象均不可见，无法确认仍在执行任务的空镜或长时间离场；
- 循环播放、复制粘贴或仅用于凑时长的重复填充片段；
- 其他经模型、确定性检测器或人工复核确认没有可用任务内容的片段。

双手正常出镜是标准视频的拍摄要求。短暂拿取工具、自然换手，或手部贴边、局部裁切等构图问题，不自动变成无效时长，应由第二维评分处理；只有手部与任务对象同时不可见、无法判断任务仍在继续时，才剔除对应时长。任务必要等待即使当时没有持续手部动作，也仍计入有效时长。

### 3.3 时间窗口

- 整片理解默认使用 `fps=0.2`，即每 5 秒抽取一帧。
- 问题片段使用 `fps=1～2` 加密分析。
- 连续且判断相同的窗口应合并为一个区间。
- 时间加权一律按毫秒或秒计算，但一次评分内必须统一单位。

### 3.4 取值与舍入

- 所有系数限制在 `[0, 1]`。
- 每维得分保留 1 位小数。
- 总分先用未舍入的分项分相加，再四舍五入保留 1 位小数。
- 分数范围限制在 `[0, 100]`。

### 3.5 不重复扣分

同一问题按根因只归入一个维度：

| 根因 | 归属维度 |
|---|---|
| 镜头不是第一人称、极端俯拍、竖屏 | 第一维 |
| 手部贴边、手/前臂/对象被裁切、拍摄过远或过近 | 第二维 |
| 模糊、曝光、抖动、冻结、掉帧 | 第三维 |
| 任务本身未完成、空转、重复、虚假或无可验证结果 | 第四维 |
| 库存饱和、近似重复、内容独特性不足 | 第五维 |

例如：任务结果因对象被裁出画面而无法看见，只扣第二维；任务结果本身没有产生，才扣第四维。

## 4. 硬性否决

### 4.1 硬性否决类型

| 原因代码 | 条件 |
|---|---|
| `BROKEN_UNPLAYABLE` | 文件损坏、无法完整解码，或主体内容 50% 以上为严重黑屏、冻结、不可识别画面 |
| `EXACT_DUPLICATE` | 文件哈希一致，或经过系统/人工确认属于同一视频的转码、裁剪、调速版本 |
| `FAKE_OR_NON_TASK` | 明确虚假任务、伪造操作，或主体并非实际物体操作任务 |
| `NON_FIRST_PERSON` | 明确第三人称达到 `T_analysis` 的 50%，或核心操作步骤 70% 以上为第三人称，且复核置信度不低于 0.90 |
| `NO_HAND_OR_OBJECT` | 主体操作时长中 70% 以上看不到任务所需手部或操作对象，且复核置信度不低于 0.90 |
| `UNRELATED_CONTENT` | 无效、无关内容达到 `T_analysis` 的 50% 以上 |
| `PRIVACY_OR_SAFETY` | 明确包含平台禁止收集的隐私、安全或合规内容 |

### 4.2 硬性否决处理

```text
raw_total_score = D1 + D2 + D3 + D4 + D5
final_score = raw_total_score
evaluation_status = hard_reject
settlement_ratio = 0
```

硬性否决不通过把总分强行改成 0 或压到 60 分以下来表达，避免丢失分项信息。
系统仍应保存其无效片段和有效计费时长，供审计与申诉使用，但最终结算金额为 0。

以下情况不能由初审模型单独自动否决：

- AI 置信度不足 0.90；
- 检测器与模型结论冲突；
- 仅根据少量抽帧推测；
- 近似重复尚未确认；
- 隐私或安全边界不明确。

这些情况必须使用复核模型复核或进入人工复核。

## 5. 总分

```text
D1 = 20 × C_view
D2 = 20 × C_hand
D3 = 20 × C_frame
D4 = 20 × C_task
D5 = 20 × C_inventory × C_unique

raw_total_score = D1 + D2 + D3 + D4 + D5
final_score = round(raw_total_score, 1)
```

## 6. 第一维：第一人称与构图规范性

### 6.1 公式

对每个视角窗口 `t`：

```text
c_view(t) =
  0.50 × c_pov(t)
+ 0.25 × c_angle(t)
+ 0.15 × c_orientation(t)
+ 0.10 × c_arm_entry(t)

C_view = Σ(duration(t) × c_view(t)) / T_analysis
D1 = 20 × C_view
```

### 6.2 第一人称真实性 `c_pov`

| 表现 | 系数 |
|---|---:|
| 明确头戴、胸戴或自然操作者第一视角 | 1.00 |
| 大概率第一人称，但证据不充分 | 0.80 |
| 固定俯拍，能看到双手但不像人眼视角 | 0.50 |
| 明显侧拍、远距离拍摄或他人拍摄 | 0.20 |
| 完全第三人称 | 0.00 |

### 6.3 视角自然度 `c_angle`

| 表现 | 系数 |
|---|---:|
| 自然向前或略向下观察 | 1.00 |
| 镜头略高、略低或轻微倾斜 | 0.80 |
| 接近垂直俯拍、画面过度居中 | 0.50 |
| 极端俯拍、仰拍或异常贴近 | 0.20 |

### 6.4 横竖屏 `c_orientation`

按旋转修正后的实际显示宽高比计算：

| `显示宽度 ÷ 显示高度` | 系数 |
|---|---:|
| `≥ 1.20` | 1.00 |
| `0.90～1.20` | 0.70 |
| `< 0.90` | 0.20 |

竖屏只影响第一维，不单独构成硬性否决。

### 6.5 手臂入镜方向 `c_arm_entry`

| 表现 | 系数 |
|---|---:|
| 双手或前臂主要从底部、下方两侧进入 | 1.00 |
| 偶尔从左右侧进入，整体仍符合第一视角 | 0.80 |
| 长时间从左右两侧或顶部进入，底部基本无手臂 | 0.40 |
| 明显正上方支架俯拍 | 0.20 |

## 7. 第二维：手部、前臂与操作对象完整度

### 7.1 公式

先识别所有需要手部操作的区间，总时长记为 `T_hand`。

对每个操作窗口 `t`：

```text
c_hand(t) = min(
  c_completeness(t),
  c_edge(t),
  c_scale(t),
  c_occlusion(t),
  c_object_visibility(t)
)

C_hand = Σ(duration(t) × c_hand(t)) / T_hand
D2 = 20 × C_hand
```

如果不存在可识别的手部操作区间，不能自动给满分；应检查是否命中 `NO_HAND_OR_OBJECT`。

### 7.2 手部与前臂完整性 `c_completeness`

| 表现 | 系数 |
|---|---:|
| 任务所需手部和主要前臂完整可见 | 1.00 |
| 前臂偶尔被裁，不影响理解 | 0.85 |
| 一只必要手频繁离开画面 | 0.60 |
| 关键操作主要在画面外完成 | 0.25 |
| 主体操作基本看不到手 | 0.00 |

单手任务只要求操作手完整。

### 7.3 手部贴边 `c_edge`

以活动手部到最近画面边缘的距离占画面短边比例计算：

| 距离比例 | 系数 |
|---|---:|
| `≥ 4%` | 1.00 |
| `1.5%～4%` | 0.85 |
| `< 1.5%` 且持续贴边 | 0.60 |
| 手部与边缘相交并被裁切 | 0.25 |
| 操作移出画面 | 0.00 |

少于 1 秒的自然进出不扣分。

### 7.4 操作区域大小 `c_scale`

操作区域指手部与对象形成的联合区域：

| 占画面比例 | 系数 |
|---|---:|
| `8%～55%` | 1.00 |
| `4%～8%` 或 `55%～70%` | 0.85 |
| `1.5%～4%`，拍摄过远 | 0.60 |
| `> 70%`，特写过大、前臂被裁 | 0.55 |
| `< 1.5%`，无法分辨细节 | 0.25 |

该阈值属于 V1 初值，应通过 500～1000 条人工标注视频校准。

### 7.5 遮挡 `c_occlusion`

| 表现 | 系数 |
|---|---:|
| 操作清楚可见 | 1.00 |
| 偶尔被身体、工具或对象遮挡 | 0.85 |
| 关键动作部分被遮挡 | 0.55 |
| 主要操作长期不可见 | 0.20 |

### 7.6 操作对象可见性 `c_object_visibility`

| 表现 | 系数 |
|---|---:|
| 对象、作用位置和操作结果完整可见 | 1.00 |
| 对象边缘偶尔被裁，不影响理解 | 0.85 |
| 关键作用位置频繁离开画面 | 0.50 |
| 只能看到手，看不到实际操作对象 | 0.20 |
| 对象和操作结果均不可见 | 0.00 |

## 8. 第三维：视频与帧质量

### 8.1 公式

```text
C_spec = min(c_resolution, c_fps)

c_visual(t) = min(
  c_sharpness(t),
  c_exposure(t),
  c_stability(t),
  c_continuity(t)
)

C_visual = Σ(duration(t) × c_visual(t)) / T_analysis
C_frame = min(C_spec, C_visual)
D3 = 20 × C_frame
```

### 8.2 分辨率 `c_resolution`

按旋转修正后的画面短边计算：

| 短边像素 | 系数 |
|---|---:|
| `≥ 1080` | 1.00 |
| `720～1079` | 0.80 |
| `540～719` | 0.55 |
| `480～539` | 0.35 |
| `< 480` | 0.15 |

高于 1080P 不额外加分。

### 8.3 帧率 `c_fps`

| 实际帧率 | 系数 |
|---|---:|
| `≥ 55fps` | 1.00 |
| `45～54fps` | 0.90 |
| `30～44fps` | 0.70 |
| `24～29fps` | 0.45 |
| `< 24fps` | 0.20 |

可变帧率视频应结合实际有效帧率和最低连续帧率，不能只使用容器声明值。

### 8.4 清晰度 `c_sharpness`

| 表现 | 系数 |
|---|---:|
| 手部、工具和对象边缘清楚 | 1.00 |
| 轻微模糊，不影响动作理解 | 0.85 |
| 细节明显丢失 | 0.55 |
| 关键动作无法看清 | 0.20 |
| 基本无法识别内容 | 0.00 |

应检查失焦、运动模糊、压缩马赛克、镜头污渍和过度降噪。

### 8.5 曝光 `c_exposure`

| 表现 | 系数 |
|---|---:|
| 曝光正常、颜色可辨 | 1.00 |
| 略暗、略亮或轻微偏色 | 0.85 |
| 大片过曝或欠曝 | 0.55 |
| 关键区域无法辨认 | 0.20 |

### 8.6 稳定性 `c_stability`

| 表现 | 系数 |
|---|---:|
| 自然头部运动，不影响观看 | 1.00 |
| 偶尔轻微抖动 | 0.85 |
| 持续明显晃动 | 0.55 |
| 剧烈抖动，无法跟踪操作 | 0.20 |

第一人称拍摄允许自然运动。

### 8.7 连续性 `c_continuity`

| 表现 | 系数 |
|---|---:|
| 播放连续，无明显异常 | 1.00 |
| 偶发短暂卡顿或重复帧 | 0.85 |
| 多次冻结、跳帧或时间戳异常 | 0.50 |
| 大段冻结、黑屏或解码失败 | 0.10 |

## 9. 第四维：任务真实性、完整度与有效操作价值

### 9.1 公式

对任务片段 `s`：

```text
c_task_segment(s) = min(
  c_level(s),
  c_authenticity(s),
  c_progress(s)
)

C_segment =
Σ(duration(s) × c_task_segment(s))
/ T_analysis

C_task = min(C_segment, C_completion)
D4 = 20 × C_task
```

### 9.2 操作价值等级 `c_level`

| 等级 | 系数 | 定义 |
|---|---:|---|
| L3 | 1.00 | 明确目标、多步骤、对象状态变化、结果可核验 |
| L2 | 0.70 | 操作真实、目标清楚、结果可见，但步骤和变化量有限 |
| L1 | 0.40 | 操作真实但过于简单、重复，新增动作信息少 |
| L0 | 0.10 | 无意义把玩、空转、反复动作，没有明确可验证结果 |
| INVALID | 0.00 | 无关内容、错误上传、广告影视、完全没有实际任务 |

长时间等待如果属于任务必要过程，可保留在任务片段中；与任务无关的等待按 `INVALID` 处理。

### 9.3 真实性 `c_authenticity`

| 表现 | 系数 |
|---|---:|
| 真实物体交互，前后状态合理 | 1.00 |
| 明显摆拍，但操作和结果真实 | 0.85 |
| 反复重置、疑似为了凑时长 | 0.50 |
| 前后状态不连续，疑似拼接或伪造 | 0.20 |
| 明确虚假任务 | 0.00 |

摆拍不等于虚假。

### 9.4 连续推进 `c_progress`

| 表现 | 系数 |
|---|---:|
| 步骤连续，每一步推动任务完成 | 1.00 |
| 有短暂停顿或少量返工 | 0.85 |
| 大量重复，但仍有缓慢进展 | 0.60 |
| 循环操作、反复恢复初始状态 | 0.30 |
| 各片段互不相关 | 0.00 |

### 9.5 完成度 `C_completion`

| 最终表现 | 系数 |
|---|---:|
| 完整展示结果，前后状态可比较 | 1.00 |
| 任务已完成，但结果展示较短 | 0.85 |
| 完成主要步骤，部分收尾缺失 | 0.65 |
| 视频中途结束，没有形成完整结果 | 0.40 |
| 没有任何可验证结果 | 0.20 |
| 明确没有执行任务 | 0.00 |

### 9.6 低价值时长折算示例

视频有效分析时长为 1808 秒，其中：

- 906 秒为 L0，系数 0.10；
- 902 秒为 L3，系数 1.00；
- 任务完成度为 1.00。

```text
C_segment = (906 × 0.10 + 902 × 1.00) / 1808 ≈ 0.55
C_task = min(0.55, 1.00) = 0.55
D4 = 20 × 0.55 = 11.0
```

低价值折扣只影响第四维，不乘整个总分。

## 10. 第五维：任务价值与独特性

### 10.1 公式

```text
D5 = 20 × C_inventory × C_unique
```

- `C_inventory`：平台库存供需系数，由结构化数据库统计。
- `C_unique`：视频独特性系数，由哈希、向量召回和片段复排结果计算。
- 模型不能自行猜测库存或伪造相似度数据。

### 10.2 库存系数 `C_inventory`

库存使用三层任务分类：

```text
场景族 → 标准任务 → 任务变体
```

```text
C_inventory =
  0.20 × C_scene
+ 0.50 × C_standard_task
+ 0.30 × C_variant
```

#### 冷启动

满足以下任一情况时，使用：

```text
C_inventory = 1.00
```

- 平台已接收有效数据总量不足 2000 小时；
- 同层级样本量不足；
- 分类结果置信度不足；
- 缺少可信库存快照。

库存饱和评分启用前，还应至少满足：

- 30 个小场景达到当期样本门槛；
- 数据覆盖不少于 30 天。

#### 小场景“样本量不足”门槛

必须同时达到时长和视频数：

| 平台累计有效时长 | 单个小场景最低时长 | 最低视频数 |
|---:|---:|---:|
| 2000～10000 小时 | 50 小时 | 300 |
| 10000～30000 小时 | 100 小时 | 500 |
| 30000～100000 小时 | 200 小时 | 1000 |
| ≥100000 小时 | 300 小时 | 1500 |

#### 相对库存模式 `relative_v1`

在同层级任务中按等效有效时长计算百分位：

| 库存百分位 | 系数 |
|---|---:|
| 后 40%，样本相对不足 | 1.00 |
| 40%～70% | 0.85 |
| 70%～90% | 0.65 |
| 前 10%，相对饱和 | 0.40 |

库存统计只计入已进入资产口径的视频；L0～L3 片段按其等级系数折算等效时长。当前待评分视频不能计入自己的库存快照。

目标模式和人工采集优先级尚未确定，V1 不自行推导目标系数。

### 10.3 综合相似度

```text
S_total =
  0.50 × S_video
+ 0.30 × S_segment
+ 0.20 × S_semantic
```

- `S_video`：整片视觉向量相似度。
- `S_segment`：相似片段覆盖时长和动作顺序相似度。
- `S_semantic`：对象、工具、动作和结果的结构化相似度。

```text
S_segment =
  0.70 × matched_duration_ratio
+ 0.30 × temporal_order_similarity
```

### 10.4 独特性系数 `C_unique`

| `S_total` | `C_unique` | 处理 |
|---|---:|---|
| `< 0.75` | 1.00 | 正常 |
| `0.75～0.85` | 0.90 | 轻微相似 |
| `0.85～0.92` | 0.70 | 明显相似 |
| `0.92～0.97` | 0.40 | 高度相似 |
| `≥ 0.97`，尚未确认重复 | 0.20 | 疑似重复，进入复核 |
| 确认完全重复 | 不适用 | 触发 `EXACT_DUPLICATE` |

### 10.5 向量查询

采用分层混合检索：

```text
文件哈希/感知哈希
→ 同任务整片向量 Top 100
→ 同场景整片向量 Top 100
→ 全库兜底 Top 50
→ 合并候选 Top 10～20
→ 片段级时序复排
→ 计算 S_total
```

D1 负责结构化数据和快照，R2 负责视频与证据文件，向量服务只负责相似候选召回。

## 11. 计费与结算

### 11.1 得分结算比例

结算比例只使用规则引擎复算后的 `final_score`：

| 最终得分 `S` | `settlement_ratio` |
|---|---:|
| `80 ≤ S ≤ 100` | 1.00 |
| `60 ≤ S < 80` | 0.80 |
| `40 ≤ S < 60` | 0.60 |
| `0 ≤ S < 40` | 0.40 |

边界值按高一档的下限处理：80 分为 `1.00`，60 分为 `0.80`，40 分为 `0.60`。普通评分视频没有最低计费分数，也不产生“通过/不通过”状态。

### 11.2 结算公式

```text
settlement_equivalent_duration =
  T_billable × settlement_ratio

settlement_amount =
  T_billable_hours × base_rate_per_hour × settlement_ratio
```

`base_rate_per_hour` 由业务价格配置提供，不由质检模型生成。

### 11.3 状态优先级

```text
if evaluation_status == hard_reject:
    settlement_ratio = 0
elif evaluation_status in [system_failed, incomplete_input, review_pending]:
    settlement_ratio = null
else:
    settlement_ratio = score_band(final_score)
```

- `hard_reject`：保留原始得分与有效计费时长，最终零结算。
- `system_failed`、`incomplete_input`、`review_pending`：暂不结算，不能误记为零结算；待处理完成后重新计算。
- `scored`：按最终得分匹配上述四档比例。
- L0～L3 真实任务片段均计入 `T_billable`；低价值影响第四维和最终得分，不再次扣除时长。

## 12. 人工复核

满足以下任一条件时设置 `review_required=true`：

- 任一维度置信度低于 0.75；
- 疑似硬性否决但不满足自动触发置信度；
- 初审模型与确定性检测器结论冲突；
- `S_total ≥ 0.92`；
- 任务分类置信度不足，导致库存系数不可靠；
- 视频处在规则阈值附近且少量误差会显著改变分数；
- 用户发起申诉。

系统处理失败必须标记为 `system_failed`，不能当作视频质量失败或给 0 分。

## 13. 千问调用标准

### 13.1 模型

| 用途 | 模型 |
|---|---|
| 整片初审、片段识别、常规问题判断 | `qwen3.7-plus` |
| 硬性否决、低置信度、争议和申诉复核 | `qwen3.7-flash` |

默认使用非思考模式和稳定模型别名；每次运行保存实际使用的模型 ID 和百炼请求 ID。

### 13.2 调用层级

1. 整片初审：直接传视频临时 URL，`fps=0.2`。
2. 问题片段：截取 10～60 秒，`fps=1～2`。
3. 条件复核：只传结构化初审结果和争议片段，不重新分析整片。
4. 输出必须是结构化 JSON，限制解释长度。

千问视频输入不分析音轨；如后续需要语音证据，应增加独立 ASR 流程。

### 13.3 不应交给千问的工作

- 分辨率、帧率、编码和时间戳读取；
- 确定性黑屏、冻结、曝光和清晰度指标；
- 文件哈希；
- 库存统计；
- 向量检索；
- 最终规则复算；
- 有效计费时长的最终合并与复算；
- 得分结算比例匹配；
- 结算金额计算。
