# 真实账户登录与管理员账户管理设计

## 1. 背景与目标

当前平台使用浏览器内的演示身份切换：登录页按角色直接进入工作台，用户、角色和团队均来自前端模拟数据。该机制不能验证用户名和密码，也不能在刷新、换设备或重新部署后保留管理员创建的账户。

本阶段将账户体系升级为真实、持久化的用户名密码登录：

- 使用统一用户名和密码登录页。
- 由管理员在现有“用户与团队”页面创建和维护账户。
- 账户、密码、登录会话、账号状态和账户操作日志保存在 D1 数据库。
- 服务端强制校验登录状态、角色和数据范围。
- 移除工作台顶部的演示角色切换，改为当前用户信息和退出登录。
- 现有视频、质检、结算、提现等业务数据仍保持演示模式。

## 2. 范围与非目标

### 2.1 本阶段包含

- 用户名密码登录和退出登录。
- 三种账户角色：管理员、团长、数采人员。
- 管理员创建管理员、团长或数采人员账户。
- 管理员编辑显示名称、用户名、角色和所属团队。
- 管理员重置密码。
- 管理员启用或停用账号。
- 登录失败限制、服务端路由保护和会话失效。
- 持久化账户操作日志。

### 2.2 本阶段不包含

- 用户自助注册。
- 首次登录强制修改密码。
- 忘记密码、短信验证码和邮件找回。
- 账号删除。
- 多设备会话管理界面。
- 第三方登录和外部 OAuth。
- 将视频、团队经营、结算或提现数据迁移到真实数据库。

## 4. 总体架构

### 4.1 持久化边界

使用 Cloudflare D1 作为账户域的唯一真实数据源。`.openai/hosting.json` 的逻辑绑定从 `d1: null` 改为 `d1: "DB"`，R2 继续保持未启用。

账户域包含三个清晰单元：

1. **账户仓储**：查询、创建和更新账户，执行唯一性与最后一个管理员保护。
2. **认证服务**：密码哈希与校验、失败限制、会话创建、会话读取和退出。
3. **账户管理接口**：验证管理员身份后调用账户仓储，并写入审计日志。

页面和客户端组件不直接访问 D1。所有数据库访问集中在服务端账户域模块和路由处理器中。

### 4.2 页面与服务端权限

公开官网 `/` 和登录页 `/login` 不要求登录。`/admin`、`/team` 和 `/collector` 及其子路径由服务端入口检查会话：

- 未登录访问工作台时跳转到 `/login`。
- 已登录访问 `/login` 时跳转到所属角色首页。
- 角色与路径不匹配时跳转到该账户自己的角色首页。
- 停用、过期或不存在的账户会话按未登录处理。

登录后的客户端导航继续沿用当前平台壳层，但直接输入地址或刷新页面时必须经过服务端校验。所有账户写接口也独立执行管理员校验，不能依赖前端菜单隐藏。

## 5. 数据模型

### 5.1 `accounts`

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | text | 主键，稳定账户 ID |
| `display_name` | text | 1–30 个字符 |
| `username` | text | 3–32 位 ASCII 字母、数字、点、下划线或连字符 |
| `username_normalized` | text | 去首尾空格并转小写，唯一索引 |
| `password_hash` | text | PBKDF2 结果，Base64URL |
| `password_salt` | text | 每个账户独立随机盐，Base64URL |
| `password_iterations` | integer | 固定为 600000，支持后续升级 |
| `role` | text | `admin`、`leader` 或 `collector` |
| `team_id` | text/null | 管理员为空，其他角色必填 |
| `status` | text | `active` 或 `disabled` |
| `failed_attempt_count` | integer | 当前失败窗口内的次数 |
| `first_failed_at` | integer/null | 失败窗口起点，Unix 毫秒 |
| `locked_until` | integer/null | 临时锁定截止时间，Unix 毫秒 |
| `created_at` | integer | Unix 毫秒 |
| `updated_at` | integer | Unix 毫秒 |

索引：

- `accounts.username_normalized` 唯一索引。
- `accounts.team_id` 普通索引，用于团长团队成员查询。
- `accounts.role, accounts.status` 组合索引，用于最后一个启用管理员检查。

管理员新建账户时使用 `U-${crypto.randomUUID()}` 作为账户 ID。`team_id` 只允许使用当前团队目录中的 `TEAM-01` 或 `TEAM-02`；管理员角色的 `team_id` 必须为空。

### 5.2 `auth_sessions`

| 字段 | 类型 | 规则 |
|---|---|---|
| `token_hash` | text | 主键，只保存会话令牌的 SHA-256 摘要 |
| `account_id` | text | 关联账户 ID |
| `created_at` | integer | Unix 毫秒 |
| `expires_at` | integer | Unix 毫秒 |

为 `account_id` 建立索引，以便重置密码或停用账号时立即删除该用户的全部会话。

### 5.3 `account_audit_logs`

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | text | 主键 |
| `actor_account_id` | text | 操作管理员 ID |
| `actor_name` | text | 操作时显示名称快照 |
| `action` | text | 创建、编辑、重置密码、启用或停用 |
| `target_account_id` | text | 目标账户 ID |
| `target_name` | text | 目标显示名称快照 |
| `summary` | text | 不包含密码的变更摘要 |
| `created_at` | integer | Unix 毫秒 |

审计日志永不记录明文密码、密码哈希、盐值或完整会话令牌。

## 6. 密码与会话安全

### 6.1 密码

- 使用 Web Crypto 的 PBKDF2-HMAC-SHA-256。
- 每个密码使用 16 字节安全随机盐和 600000 次迭代。
- 新建和重置的密码长度为 8–64 个字符。
- 数据库永不保存或返回明文密码。
- 密码比较使用字节级恒定时间比较。

### 6.2 登录失败限制

- 同一账户在 15 分钟窗口内连续失败 5 次后锁定 15 分钟。
- 失败窗口超过 15 分钟时，从下一次失败重新计数。
- 登录成功后清空失败次数、窗口时间和锁定时间。
- 不存在的用户名也执行一次等价的密码计算，并统一返回“用户名或密码错误”，避免通过响应差异枚举账户。
- 已锁定账号返回剩余等待时间。
- 停用账号返回“账号已停用，请联系管理员”。

### 6.3 会话

- 登录成功后生成 32 字节安全随机令牌。
- 浏览器只通过名为 `evdp_session` 的 Cookie 保存原始令牌。
- 数据库只保存令牌的 SHA-256 摘要。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`、`Path=/`；正式 HTTPS 环境启用 `Secure`。
- 会话有效期固定为 7 天。
- 退出登录删除当前会话和 Cookie。
- 重置密码或停用账号时删除该账户的全部会话。
- 每次鉴权都联查账户状态和角色，角色调整无需等待旧会话过期。

所有改变状态的账户接口只接受 JSON，并校验请求 `Origin` 与当前站点同源。

## 7. 服务端接口

### 7.1 认证接口

- `POST /api/auth/login`
  - 输入：`{ username, password }`
  - 成功：写入会话 Cookie，返回账户的 `id`、`displayName`、`role`、`teamId` 和角色首页。
- `POST /api/auth/logout`
  - 删除当前会话并清除 Cookie。
- `GET /api/auth/session`
  - 返回当前账户的安全公开字段，不返回密码相关字段。

### 7.2 管理员账户接口

以下接口全部要求当前账户为启用状态的管理员：

- `GET /api/admin/accounts`
  - 返回账户列表和团队显示信息。
- `POST /api/admin/accounts`
  - 创建管理员、团长或数采人员。
- `PATCH /api/admin/accounts/:id`
  - 修改显示名称、用户名、角色和团队。
- `POST /api/admin/accounts/:id/reset-password`
  - 写入新密码哈希并使该账户全部会话失效。
- `POST /api/admin/accounts/:id/status`
  - 启用或停用账户；停用时使该账户全部会话失效。

账户修改、会话删除和审计日志写入使用 D1 批处理完成，避免只完成一部分。

## 8. 业务数据衔接

D1 账户是用户身份、角色、团队归属和状态的真实来源。服务端根据当前登录角色返回最小必要账户范围：

- 管理员获取全部账户。
- 团长只获取本团队账户。
- 数采人员只获取本人账户。

`DemoStoreProvider` 接收服务端账户快照，并用它覆盖 `demoSeed.users` 中的身份字段。团队领导和成员关系根据账户角色与 `teamId` 重建。管理员新增或编辑账户成功后，前端同时更新当前账户快照，因此用户列表和团队成员列表立即一致；刷新后再从 D1 恢复。

现有提交记录、提现记录、审计记录中的人员显示名称更新为“管理员”“团长1/2”和“测试人员1–5”。新创建但没有业务记录的账户只出现在用户与团队相关界面，不生成虚假提交、收入或结算数据。

`/admin/audit` 将持久化账户操作日志与现有业务演示日志合并展示；账户日志刷新页面后仍然存在，业务演示日志继续遵循当前会话规则。

## 9. 页面与交互设计

### 9.1 登录页

保留现有左右分栏视觉结构，将三张演示身份卡替换为：

- 用户名输入框。
- 密码输入框。
- 显示或隐藏密码按钮。
- 登录按钮和提交中状态。
- 表单级错误提示。
- 返回官网入口。

登录页不展示初始密码，不提供自助注册、忘记密码或角色选择。

### 9.2 工作台顶部

- 删除“演示角色”下拉选择。
- 保留当前用户头像、显示名称和角色。
- 增加“退出登录”按钮。
- 退出成功后跳转到 `/login`。

### 9.3 用户与团队

保留现有管理员菜单“用户与团队”，在同一页面中增强账户管理：

- 搜索显示名称或用户名。
- 按角色、团队和状态筛选。
- 列表展示显示名称、用户名、角色、团队、状态和更新时间。
- “新增账号”弹窗包含显示名称、用户名、初始密码、角色和所属团队。
- “编辑账号”弹窗允许修改显示名称、用户名、角色和所属团队。
- “重置密码”使用独立确认弹窗，输入新密码并二次确认。
- “启用／停用”操作在执行前确认。

管理员角色不选择团队；团长和数采人员必须选择有效团队。用户名忽略大小写后必须唯一。

系统允许管理员创建新的管理员。当前管理员不能在自己的登录会话中停用自己；任何操作都不能停用或降级最后一个启用管理员。账号不提供删除操作。

## 10. 错误处理

- 表单校验失败时保留用户已输入内容。
- 重复用户名提示“用户名已存在”。
- 用户名格式不符合要求时提示“用户名需为 3 到 32 位字母、数字、点、下划线或连字符”。
- 显示名称为空或超过 30 个字符时提示“显示名称需为 1 到 30 个字符”。
- 团长或数采人员缺少有效团队时提示“请选择有效团队”。
- 两次密码不一致时提示“确认密码与新密码不一致”。
- 密码长度不符合要求时提示“密码长度需为 8 到 64 位”。
- 最后一个启用管理员保护提示“系统必须保留至少一个启用的管理员”。
- 当前管理员尝试停用自己时提示“不能停用当前登录账号”。
- 网络或服务端异常显示“操作失败，请稍后重试”，不伪造成功状态。
- 登录按钮和管理员写操作按钮在请求期间禁用，防止重复提交。

## 11. 数据初始化与迁移

- 在 `db/schema.ts` 定义三个账户域表和实际查询需要的索引。
- 使用 Drizzle 生成并提交 SQL 迁移。
- 首次账户请求时执行幂等初始化：仅当 `accounts` 表为空时插入第 3 节的八个初始账户。
- 初始密码在初始化过程中生成独立盐值和哈希，不把明文写入数据库或迁移 SQL。
- 并发初始化通过账户主键与用户名唯一约束以及 `INSERT OR IGNORE` 保证结果唯一。
- 部署时由 Sites 创建并绑定 D1，迁移文件随版本一起发布。

## 12. 测试策略

### 12.1 单元测试

- 密码哈希不会等于明文，正确密码通过，错误密码失败。
- 用户名标准化、密码长度和角色团队校验。
- 失败计数、15 分钟锁定和成功登录重置。
- 会话令牌只以摘要形式入库。
- 最后一个启用管理员和当前管理员停用保护。

### 12.2 服务端集成测试

- 登录成功设置安全 Cookie，错误密码不设置 Cookie。
- 停用、锁定和过期会话被拒绝。
- 三种角色访问自己的工作台成功。
- 未登录和跨角色直接访问被服务端重定向。
- 非管理员调用账户管理接口返回 403。
- 创建、编辑、重置密码和启停账户持久化并写入审计日志。
- 重置密码和停用账户立即删除该账户全部会话。

### 12.3 页面交互测试

- 搜索、筛选、编辑、重置密码和启停操作。
- 重复用户名、无效团队、弱密码和最后一个管理员错误。

### 12.4 回归与部署验证

- 现有 72 项交互测试继续通过。

## 13. 验收标准

- 用户不能再通过角色卡或顶部下拉框绕过登录和权限。
- 八个初始账户可以使用第 3 节凭据登录到正确工作台。
- 管理员可以创建管理员、团长和数采人员账户，并在刷新后继续看到。
- 管理员可以编辑账户、重置密码、启用和停用账户。
- 密码、完整会话令牌和重置密码内容不出现在数据库查询结果、接口响应或审计日志中。
- 未登录、停用账号和跨角色访问在服务端被拒绝。
- 系统始终保留至少一个启用管理员。
- 现有业务演示流程不因真实账户体系而回归。
