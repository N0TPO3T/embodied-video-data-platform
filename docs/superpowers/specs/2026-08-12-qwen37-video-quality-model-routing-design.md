# AI 视频质检 Qwen3.7 模型路由设计

## 目标

将 AI 视频质检的默认模型路由调整为：

- 初审：`qwen3.7-plus`
- 条件复核：`qwen3.7-flash`

继续使用当前百炼工作空间专属 OpenAI 兼容地址、`chat/completions` 接口、多帧视频输入、结构化 JSON 输出、中文结果门禁和 `video_qc_v1` 规则。模型路由调整不得改变五维评分、硬性否决、有效计费时长或结算算法。

## 已确认的模型能力

当前百炼工作空间的 `/models` 接口同时返回 `qwen3.7-plus`、`qwen3.7-plus-2026-05-26`、`qwen3.7-flash` 和 `qwen3.7-flash-2026-07-15`。本次使用不带日期的稳定别名，使工作空间可以跟随百炼对别名的版本维护。

Qwen3.7 系列支持项目当前使用的图像列表视频输入、OpenAI 兼容 Chat Completions、非思考模式结构化输出以及中文文本输出，因此不更换 Provider 协议或媒体预处理方式。

## 模型路由

每条视频完成媒体预处理后，固定由 `qwen3.7-plus` 执行初审。初审负责整片理解、五维候选评分、问题片段、扣分说明、改进建议以及是否需要复核的判断。

只有符合现有复核条件时才调用 `qwen3.7-flash`：

- 模型输出 `review_required=true` 或 `evaluation_status=review_pending`；
- 出现硬性否决候选；
- 任务分类或任一维度置信度低于 `0.75`；
- 规则引擎发现校验错误；
- 相似度达到现有复核阈值。

中文或结构修复继续使用当前正在执行的模型：初审结果修复使用 `qwen3.7-plus`，复核结果修复使用 `qwen3.7-flash`。修复调用不改变业务阶段。

## 阶段命名与历史兼容

新任务使用与模型档位无关的阶段名：

- `initial_review`：初审
- `secondary_review`：复核

模型运行元数据和百炼诊断分别使用 `initial`、`review`，不再写入 `flash`、`plus`。页面显示“初审”“复核”，实际模型名称仍在健康状态、诊断和完整结果中展示。

为兼容已经持久化的 30 天任务历史，读取与页面展示继续接受旧值：

- `flash_review` 显示为“初审（历史）”
- `plus_review` 显示为“复核（历史）”
- 旧诊断中的 `modelStage=flash|plus` 保持可读

不会批量改写已有历史文件。所有新任务只写入新阶段名称。

## 配置与文档

以下位置统一更新：

- 运行环境默认值和根目录本地 `.env`；
- `.env.example`；
- V1 提示词中的推荐模型与复核模型元数据；
- V1 评分规则的模型基线与路由表；
- README 实验页说明；
- 质量实验页和正式流程共享的模型配置；
- 单元测试、服务测试和 Provider 请求断言。

仍保留 `VIDEO_QUALITY_INITIAL_MODEL` 和 `VIDEO_QUALITY_REVIEW_MODEL` 环境变量，便于将来灰度或回滚。启动时继续校验环境变量配置与提示词元数据一致，避免页面显示一种模型而 Provider 实际调用另一种模型。

## 错误处理

模型不存在、工作空间未授权、请求格式不兼容或网络失败时，沿用现有任务级脱敏诊断和错误展示。复核失败仍保留初审结果并进入“待复核”，但提示改为“复核失败”，不再写死 Plus。

本次不主动对真实视频发起付费模型请求。验证包括工作空间 `/models` 可用性查询、Provider 请求体测试、完整自动测试、构建、容器健康检查和页面文案检查。

## 非目标

- 不调整评分提示词的业务规则和 JSON 契约。
- 不调整抽帧频率、复核窗口或重试次数。
- 不增加第三个模型或新的模型选择页面。
- 不删除或迁移旧任务历史。
