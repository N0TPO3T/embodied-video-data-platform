# 具身视频数据平台基础交互增强设计

- 文档状态：已确认设计
- 编写日期：2026-08-03
- 交付阶段：一期前端框架交互增强
- 基线版本：`main` 分支 `d853f4a`
- 关联设计：`docs/superpowers/specs/2026-08-03-clickable-platform-framework-design.md`

## 1. 目标

在现有可点击平台框架上补齐基础交互，使主要按钮不再出现点击无响应，并让团长和管理员的代表性业务操作能够通过表单真实更新演示数据。

本阶段继续使用浏览器内内存状态。操作结果在页面切换和角色切换期间保持一致，刷新页面后恢复初始演示数据。不接入真实后端、浏览器持久化、文件导出服务、支付或消息服务。

## 2. 实现方案

采用“统一演示数据仓库 + 共享交互组件”的实现方式。

- 业务状态变化由演示数据仓库统一处理，避免各页面维护互不一致的临时数据。
- 弹窗、确认、提示和通知由共享组件处理，保证交互样式、关闭方式和错误反馈一致。
- 仅需要展示反馈的操作不创建伪造业务数据，而是通过全局提示明确说明演示结果。
- 所有新增命令保持未来可替换为真实 API 的接口形态。

不采用页面内分散状态，因为切换页面后数据会不一致；不引入完整工作流引擎，因为当前框架不需要服务端任务编排和持久状态机。

## 3. 共享交互层

### 3.1 全局提示

新增统一的成功、错误和信息提示组件：

- 默认显示在工作台右上角，移动端显示在顶部内容区域。
- 成功和信息提示在短暂展示后自动关闭。
- 表单校验错误优先显示在表单内部，不依赖自动关闭提示。
- 同一时间最多展示三条提示，避免连续操作遮挡页面。

### 3.2 表单弹窗与确认弹窗

业务表单使用统一弹窗组件：

- 支持遮罩、关闭按钮和 `Esc` 键关闭。
- 点击弹窗内容不会触发遮罩关闭。
- 提交期间禁用重复提交并展示处理中状态。
- 必填项、格式错误和业务冲突在字段附近或表单底部明确显示。
- 桌面端使用居中弹窗，移动端使用接近全屏的底部面板。

需要用户确认的不可逆演示动作使用确认弹窗，不使用浏览器原生确认框。

### 3.3 通知面板

顶部通知按钮打开通知面板，展示至少三条模拟通知：

- 团长待处理的结算前复核。
- AI 任务异常。
- 提现或结算状态变化。

用户可以执行“全部标为已读”。完成后通知红点消失，并显示成功提示。已读状态只在当前演示会话中保留。

## 4. 业务交互

### 4.1 团长邀请成员

入口位于团队首页和成员管理页。

表单字段：

- 成员姓名，必填。
- 手机号，必填，使用简化的中国大陆手机号格式校验。

提交成功后：

- 创建新的数采人员演示账号。
- 加入当前团长所在团队。
- 成员管理列表和团队成员数量立即更新。
- 显示“成员已加入团队”的成功提示。

相同手机号已存在时拒绝提交并显示错误。

### 4.2 查看成员详情

成员列表的“查看”按钮打开只读详情弹窗，展示账号、角色、团队、手机号、当日上传、有效时长和通过率。弹窗不提供移除成员功能，避免在本阶段引入破坏性组织操作。

### 4.3 管理员新增与配置用户

新增用户表单字段：

- 姓名。
- 登录账号。
- 角色。
- 所属团队；数采人员和团长必填，管理员不需要团队。

账号必须唯一。提交成功后用户列表和统计数量立即更新。

用户列表的“配置”按钮打开编辑表单，可修改角色和团队归属。姓名与账号作为演示身份标识保持只读。保存成功后更新用户和对应团队成员关系。

每个团队只能有一位团长。将用户设置为团长时，该用户成为所选团队的新团长，原团长自动调整为该团队的数采人员；将现任团长改为其他角色前必须先指定替代团长。

### 4.4 创建与编辑规则

“新建规则版本”打开规则表单，填写版本名称、通过阈值和说明。创建成功后当前规则卡片显示新版本，并增加一条操作日志。

标签列表的“编辑”按钮打开标签编辑表单，可修改显示名称和启用状态。保存后更新当前列表并显示成功提示。

质量系数分档在本阶段保持现有固定业务规则，不允许通过表单修改。

### 4.5 生成结算批次

“生成演示批次”打开确认弹窗，展示当前所有未结算且质量通过的视频数量、有效时长和预计总金额。

确认后：

- 创建新的已锁定结算批次。
- 将纳入批次的数据设置为已结算。
- 新批次出现在结算列表顶部。
- 对应数据不再允许质量调整。
- 写入一条模拟操作日志并显示成功提示。

没有符合条件的数据时禁用确认操作并说明原因。

### 4.6 创建交付包

“创建交付包”打开表单，填写交付包名称，并展示当前已结算且质量通过的资产数量。

提交成功后：

- 创建一条会话内交付包记录。
- 数据资产页的本月交付包数量增加。
- 显示“交付包已创建”的成功提示。

交付包只记录名称、资产数量、创建时间和状态，不生成真实压缩文件或下载地址。

## 5. 轻量反馈交互

以下操作不改变核心业务状态，但必须提供明确反馈：

- 官网“了解生产流程”：平滑滚动至生产流程区域。
- 数据提交“导出当前结果”：提示导出任务已创建，不生成文件。
- 操作日志“导出日志”：提示导出任务已创建，不生成文件。
- 现阶段尚未接入真实服务的辅助操作：显示统一的演示说明提示。

不新增虚假的网络加载，不模拟长时间后台任务。

## 6. 数据模型与命令

演示状态新增：

- 交付包列表。
- 当前规则版本和标签配置。
- 通知已读状态由交互层维护，不写入业务仓库。

演示数据仓库新增命令：

- `inviteMember(input)`
- `addUser(input)`
- `updateUser(input)`
- `createRuleVersion(input)`
- `updateLabel(input)`
- `createSettlementBatch()`
- `createDeliveryPackage(input)`

每个命令负责业务校验、不可变状态更新和错误消息。页面只负责收集输入和展示结果。

## 7. 异常与边界

- 必填字段为空时不提交。
- 手机号格式错误或重复时拒绝邀请。
- 登录账号重复时拒绝新增用户。
- 团长只能向自己的团队邀请成员。
- 结算只包含未结算、处理完成且质量通过的数据。
- 交付包只能统计已结算且质量通过的数据资产。
- 连续点击提交按钮不会创建重复记录。
- 弹窗关闭后清空未提交的表单和错误信息。
- 切换角色后仍能看到同一会话内已有的业务状态变化。

## 8. 可访问性与响应式

- 弹窗具有可访问名称，首次打开后焦点进入首个可编辑字段。
- `Esc` 可关闭弹窗，关闭后焦点返回触发按钮。
- 表单字段具有明确标签，错误信息可被辅助技术读取。
- 所有按钮保留键盘焦点样式和至少 40 像素触控区域。
- 移动端弹窗、通知面板和提示不会超出视口或遮挡主要提交按钮。

## 9. 测试与验收

自动化测试至少覆盖：

- 邀请成员成功后更新当前团队成员列表。
- 重复手机号无法邀请。
- 新增用户成功且重复账号被拒绝。
- 用户配置能够改变角色和团队归属。
- 结算批次正确锁定符合条件的视频，已结算数据不可再次复核。
- 创建交付包后数量更新。
- 规则版本和标签编辑更新页面状态。
- 通知全部已读后红点消失。
- 官网流程按钮触发目标区域滚动。
- 导出按钮提供明确反馈。
- 弹窗支持关闭、`Esc` 和重复提交保护。
- 完整测试、类型检查、生产构建和服务端渲染验证通过。

## 10. 明确不实现

- 刷新后的状态持久化。
- 真实邀请短信、账号密码和权限服务。
- 真实 CSV、ZIP 或数据资产下载。
- 真实消息中心和推送服务。
- 真实结算账本、支付和资金流水。
- 批量选择资产、交付审批和采购商下载。
- 删除用户、移除成员和回滚结算批次。
