# AI 质检任务历史与调用诊断设计

## 目标

独立 AI 视频质检实验页必须在浏览器刷新和容器重启后恢复最近 30 天任务。每个任务使用服务端生成的固定 `LAB-...` ID，并可据此查看评分结果及脱敏百炼调用诊断。

## 持久化边界

- 使用实验服务自己的本地 JSON 文件，不依赖 PostgreSQL、Redis、MinIO 或 RabbitMQ。
- Docker 通过命名卷保存该文件，默认路径 `/data/quality-lab/jobs.json`。
- 保存任务 ID、批次 ID、原始文件名、文件大小、状态、时间、评分结果、公开错误和诊断记录。
- 不保存上传视频、抽帧、API Key、Authorization 请求头、Base64 内容、请求正文或完整模型回复。
- 终态任务保留 30 天；读取、创建任务时清理过期记录。
- 服务启动时，历史中的非终态任务统一标记为 `system_failed`，错误为“服务重启导致任务中断，请重新上传”。

## 诊断记录

每次 Flash、Plus 或结构修复请求均记录一次调用尝试，包括：任务 ID、模型阶段、模型 ID、尝试序号、开始/结束时间、耗时、结论、HTTP 状态、百炼 `request_id`、是否可重试，以及脱敏后的网络错误名称、错误码和简短信息。

诊断同时写入任务历史和容器结构化日志。错误清理必须过滤 API Key 形态、Bearer 值、临时路径和 Data URL。

## API 与页面

- `GET /api/jobs` 返回按创建时间倒序的 30 天任务历史。
- `GET /api/jobs/:id` 返回单项详情和诊断。
- `DELETE /api/jobs/:id`：运行中任务取消；终态任务删除历史。
- 上传响应继续返回后端任务 ID。
- 页面加载时请求历史列表并恢复队列和结果；队列与结果卡片均显示可复制的任务 ID。
- 下载的单项和整批 JSON 包含任务 ID及诊断。

## 验证

覆盖写盘与重载、30 天清理、重启中断恢复、任务列表/删除、诊断脱敏、页面历史加载与任务 ID 展示，并运行后端完整测试、类型检查、构建和容器健康检查。自动测试不得调用百炼。
