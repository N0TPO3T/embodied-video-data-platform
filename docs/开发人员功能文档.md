# 具身智能视频数据平台 · 开发人员功能文档

> 面向技术开发/运维人员，说明当前已实现的功能、架构、数据模型、部署方式与待办事项。
> 更新日期：2026-08-24

---

## 1. 项目概览

具身智能视频数据平台（Embodied Data）是一个面向具身智能视频数据生产的一体化平台，实现「采集上传 → 媒体解析 → AI 质检 → 人工复核 → 积分结算 → 资产交付」的完整链路。

| 项 | 说明 |
|---|---|
| 后端 | NestJS + TypeORM + PostgreSQL（API 服务） |
| 前端 | vinext（基于 Next.js App Router 的构建框架）+ React + Vite |
| 媒体处理 | FFmpeg / FFprobe（独立 worker） |
| AI 质检 | 阿里云百炼 Qwen3.7（`qwen3.7-plus` 初检 / `qwen3.7-flash` 条件复核） |
| 消息队列 | RabbitMQ（可靠消息 / outbox 驱动） |
| 缓存/会话 | Redis |
| 对象存储 | MinIO（本地默认）/ 阿里云 OSS（生产，S3 兼容 API） |
| 反向代理 | Nginx（gateway 容器） |

## 2. 架构与服务拓扑

### 2.1 服务组成（Docker Compose）

| 服务 | 职责 |
|---|---|
| `postgres` | PostgreSQL 17，业务主库 |
| `redis` | Redis 8，会话/限流/缓存 |
| `rabbitmq` | RabbitMQ 4（management），媒体与 AI 队列 |
| `api` | NestJS API（:4000），迁移 + 业务逻辑 |
| `media-worker` | 消费媒体消息，FFprobe/FFmpeg 解析与派生资产 |
| `ai-quality-worker` | 消费 AI 质检消息，调用百炼模型 + 规则引擎复算 |
| `web` | vinext 前端（:3000，生产 standalone） |
| `gateway` | Nginx，反代 `/api/*` 到 api、`/` 到 web（:80） |
| `ai-quality-lab` | 独立 AI 质检实验页（`--profile ai-test`，非主流程） |

### 2.2 生产拓扑

- `compose.yaml`：本地基础设施 + api/media-worker/ai-quality-worker + ai-quality-lab。
- `compose.prod.yaml`：追加 `web`、`gateway`；api 启动前先跑 `run-migrations.js`；关闭本地默认密码许可。
- `deploy/nginx.conf`：统一入口，`/api/` 反代 api，其余反代 web。

### 2.3 健康检查

- 存活：`GET /api/v1/health/live`
- 就绪（含 PostgreSQL 可用性）：`GET /api/v1/health/ready`

## 4. 已实现功能

### 4.1 身份与权限

- 用户名密码登录、会话管理、退出、登录失败限流、过期会话自动清理（启动/定时/登录时）。
- 三类角色：`admin` / `leader` / `collector`，前端路由与后端接口双重角色隔离。
- 密码 Argon2id 哈希；重置密码/改密/角色或团队变更会撤销旧会话。
- 生产模式拦截本地默认密钥与预设账号密码（`EVDP_ALLOW_LOCAL_DEFAULT_PASSWORDS=false`）。
- 敏感写接口带服务端频率限制（`SensitiveActionRateLimitGuard`）+ 来源校验（`AllowedOriginGuard`）。

### 4.2 团队管理

- 团队增删改、启停、唯一团长任命（原子更换）、跨团队调配账号、团队单价 `unit_price_per_minute` 覆盖默认积分单价。

### 4.2.1 采集任务（任务化组织）

- 管理员在线创建任务：标题、说明、场景名称（输入带标签字典补全）、自由填写任务要求、按分钟定价（可空回退全局）。
- AI 要求规范化：自由文本 → 文本模型（`TASK_REQUIREMENT_NORMALIZER_MODEL`，默认 `qwen3.7-plus`）输出结构化条目（`scene_description` + `requirements[{type: hard|soft, content, rationale}]` + `quality_notes`）→ 管理员预览、可编辑、确认后任务才可发布。
- 生命周期：`draft → published ⇄ paused → closed`（closed 不可逆）；暂停/关闭只阻止新提交，在途数据继续处理。
- 全新场景发布时自动加入标签字典（复用标签版本机制，生成新版本并写入审计），管理员可在「标签与规则」停用错录场景。
- 任务编辑后需重新规范化并确认；发布递增 `revision`，提交时锁定任务快照。
- 审计动作：`task_create / task_update / task_normalize_confirm / task_publish / task_pause / task_resume / task_close`。

### 4.3 视频上传与媒体处理

- MP4/MOV 分片上传（16 MiB 分片、并发 3、单文件 2 GiB 上限、URL 有效期 15 分钟）。
- 暂停/继续/取消/失败重试；刷新或换设备后按「同名 + 同大小 + SHA-256」恢复未完成上传。
- 上传前授权确认（数据使用权/隐私/敏感内容）+ **任务选择与任务要求确认**，前端阻断 + 后端二次校验，记录确认版本与时间。
- 上传创建时校验任务状态（必须 `published`）并把任务快照（`task_id / task_revision / task_scene_name / task_requirements_snapshot / task_price_points_per_minute`）写入 `submissions`。
- SHA-256 完全重复拦截；媒体解析后生成**近似重复候选**（时长/大小/分辨率/帧率元数据相似度）。
- 媒体派生资产：低码率 MP4、HLS 多码率清单/分片、封面图、问题片段证据帧。
- 黑屏/冻结等技术性无效片段检测。

### 4.4 AI 质检

- `qwen3.7-plus` 整片初检 + `qwen3.7-flash` 条件复核，worker 内并发默认 3（`AI_QUALITY_CONCURRENCY`，1~32 可调），三级延迟重试。
- 五维评分，`每维得分 = 20 × 系数`，总分 100；服务端**规则引擎复算**模型分数与系数一致性。
- 五维：
  - D1 第一人称与构图（`first_person_and_composition`）
  - D2 手部/前臂/对象完整度（`hand_forearm_object_integrity`）
  - D3 帧与视频质量（`frame_and_video_quality`）
  - D4 任务维度（`task_authenticity_completeness`）：提供任务要求时 = **任务符合度**（场景匹配 + 要求逐条判定，服务端按 met=1/partial=0.5/unmet=0 复算 D4 并重算总分；hard 未满足或场景不匹配→人工复核）；未提供时 = 通用任务真实性与完成度
  - D5 任务价值与独特性（`task_value_uniqueness`，`20 × C_inventory × C_unique`）
- 提示词 = 通用框架 v2（`docs/quality/prompts/qwen-video-ai-quality-framework-v2/`，`video_qc_v2` / `qwen_video_qc_prompt_v4`）+ 任务要求区块（提交时锁定快照）；无任务历史数据仅用框架。
- 输出含 `task_compliance` 区块（`scene_match` + 逐条 items + compliance_ratio），经 Zod schema 校验，失败进入 `system_failed`。
- 终态：`scored` / `hard_reject` / `review_pending` / `system_failed` / `incomplete_input`。
- 硬性否决：文件损坏、完全重复、虚假任务、第三人称、无手/对象、与任务场景无关、隐私安全等。
- 提示词版本化（`video_quality_prompt_versions`）；【任务分类输出】模型从标签字典选 `scene_id / standard_task_id / variant_id` 并回写到 `media_metadata`，提供任务时 scene 优先与任务场景一致。
- 结果持久化 PostgreSQL，含模型调用元数据、提示词/规则/标签/任务要求快照；重跑生成新记录不覆盖历史。
- 失败任务可人工重跑、超时任务可重新排队、Worker 心跳与耗时统计。

### 4.5 标签、规则、稀缺奖励

- **标签体系**（`label_set_versions`）：场景/动作/对象/问题四类，默认 33 条（18 场景 + 8 动作 + 4 对象 + 3 问题）；管理员可**新增/编辑/删除**，每次生成新版本快照。
- **质量规则**（`quality_rule_versions`）：通过阈值 + 说明，版本化。
- **积分规则**（`point_rule_versions`）：默认每分钟积分 + 质量系数分档 + 说明，版本化；分档可增删改。
- **稀缺奖励**（`scarcity_config`）：按「场景 → 标准任务 → 变体」存量分档计酬，默认权重 0.2/0.5/0.3，分档 0-5→1.0、6-20→0.9、21-50→0.75、51-100→0.6、101+→0.5；无场景归类或配置关闭时冷启动系数 1.0。
- 库存上下文（`inventory.service.ts`）：实时从 `media_metadata`（含 scene_id/task_id/variant_id）join 提交表统计，排除隔离/删除/自身。
- 新 AI 任务锁定提示词/规则/标签版本；新积分周期锁定积分规则版本（快照）。

### 4.6 积分与结算

- 积分规则：默认 `12 分/分钟`；质量系数分档默认 80-100→1.0、70-79→0.85、60-69→0.7、0-59→0。
- 积分公式：`积分 = 每分钟积分 × 有效计费时长(分钟) × 结算比例`（`pointsForRule`）。
- **按任务定价**：每分钟积分单价优先级为任务快照单价 > 团队单价 > 全局默认积分；周期明细与 CSV 导出包含任务快照列（task_id/task_name/task_scene_name/price_points_per_minute）。
- 结算比例：得分低于通过阈值（默认 60）或硬性否决 → 0；否则按分档系数（`settlementRatioForScore`）。
- 积分周期（`point_cycles`）：按业务日期唯一，管理员手动锁定；每条视频生成明细快照（`point_cycle_items`）。
- 锁定后调整（`point_cycle_adjustments`）：最新生效（distinctOn itemId），记录前后快照、积分差额、原因，写审计；支持对单条视频改最终分与无效时长。
- 周期/明细支持按角色范围 CSV 导出。

### 4.7 人工复核与敏感隔离

- 管理员复核候选 = 质量通过且未入周期的数据 + 近似重复候选。
- 复核可改最终分、问题区间、原因、复核人/时间，写审计，产生调整流水（不覆盖原快照）。
- 敏感视频隔离/解除隔离：隔离后不进待结算资产、交付包候选、公开统计。

### 4.8 交付与资产

- 交付包（`delivery_packages`）、资产条目（`delivery_package_items`）、资产 CSV 清单。
- 短期签名资产下载链接；zip/tar 一键归档；可追踪异步归档任务（`delivery_archive_tasks` + lease）。
- 对象治理：默认保留 180 天（`SUBMISSION_OBJECT_RETENTION_DAYS`），删除对象同步删原视频/预览/HLS/封面/证据帧并标记状态，未到期需强制删除。

### 4.9 公开站点与审计

- 公开官网：定位、脱敏指标、场景能力、生产流程、质量保障、登录入口。
- 公开快照（`public_site_snapshots`）：从质检通过数据生成，管理员发布，写审计。
- 审计日志（`audit_logs`）：服务端关键词/操作人/动作/时间范围筛选、分页、CSV 导出。

### 4.10 运维

- Worker 心跳、当前任务、运行耗时、完成/失败数、平均/最近/最长耗时、过久任务告警。
- 顶部通知中心 + 导航角标：按角色范围展示待处理/失败/复核/积分锁定提醒。
- GitHub Actions CI；数据库迁移发布/回滚、容量/性能验收、告警起点见 `docs/operations/release-readiness.md`。

## 6. 关键流程

```text
管理员创建采集任务（自由填写要求 → AI 规范化 → 预览确认 → 发布，全新场景自动入字典）
  → 数采任务大厅选择任务 → 确认任务要求 → 上传（分片/断点续传/授权确认/SHA-256 去重，锁定任务快照）
  → 媒体解析（FFprobe/FFmpeg：元数据、预览、HLS、封面、证据帧、黑屏冻结、近似重复候选）
  → AI 质检（通用框架 v2 + 任务要求区块 → qwen3.7-plus 初检 → 条件 qwen3.7-flash 复核 → Zod 校验 → 规则引擎复算 → 任务符合度复算 → 场景归类回写）
  → 终态（scored / hard_reject / review_pending / system_failed）
  → 人工复核（可选，改分留痕）
  → 积分周期锁定（任务快照单价 × 质量系数 → 明细快照 → 锁定后调整）
  → 数据资产交付（交付包 / CSV / 签名链接 / zip-tar 归档）
```

## 7. 对象存储：MinIO / OSS

存储抽象在 `backend/src/storage/`，通过 S3 兼容 API 同时支持 MinIO（本地）与阿里云 OSS（生产）。

生产 OSS 相关环境变量：

```dotenv
MINIO_BUCKET=zrcs-shucai
MINIO_ENDPOINT=https://s3.oss-cn-hangzhou-internal.aliyuncs.com      # ECS 同地域内网
MINIO_PUBLIC_ENDPOINT=https://s3.oss-cn-hangzhou.aliyuncs.com        # 公网（签名 URL）
MINIO_ACCESS_KEY=...
MINIO_SECRET_KEY=...
MINIO_REGION=cn-hangzhou
MINIO_FORCE_PATH_STYLE=false                                          # OSS 虚拟主机风格
```

本地默认：

```dotenv
MINIO_ENDPOINT=http://minio:9000
MINIO_PUBLIC_ENDPOINT=http://localhost:9000
MINIO_REGION=us-east-1
MINIO_FORCE_PATH_STYLE=true
```

## 10. 部署

生产部署为「服务器手动拷贝 + Docker Compose」（服务器非 git 仓库，本地仓库为唯一真源）。核心命令：

```bash
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
docker compose -f compose.yaml -f compose.prod.yaml up -d --force-recreate   # 代码变更后重建
```

- 服务器文件同步：`workbench upload`（阿里云 ECS CLI）上传改动文件 → 解包 → 重建镜像。
- 迁移：api 容器启动时自动执行 `node dist/database/run-migrations.js`。
- 网关 502 排查：先 `--force-recreate gateway`（Nginx 缓存了上游 DNS），再查 web。
- 提示词/规则文件权限：`docs/quality` 需 `chmod -R a+rX`（worker 以非 root 运行）。
