# 任务化改造设计方案

> 文档状态：设计稿（待评审）
> 日期：2026-08-24
> 范围：将平台从「无任务直接上传 + 固定质检提示词」改造为「管理员在线发布采集任务（场景 + 要求）→ 数采人员按任务提交视频 → AI 质检 = 通用提示词框架 + 任务规范化要求」。

---

## 1. 背景与目标

### 1.1 现状

- 数采人员上传视频**不绑定任何任务**，系统对提交内容无前置限制。
- AI 质检使用一份**固定且高度具体**的提示词（`video_qc_v1`，D1~D5 五维评分硬编码在 `docs/quality/prompts/qwen-video-ai-quality-prompt-v1/system.txt`），管理员只能整体编辑并强制保留 `video_qc_v1`/JSON 约束。
- 积分结算：全局「每分钟积分 × 质量系数档位」，按周期锁定。
- 组织模型：管理员 → 团长 → 数采人员（团队归属）。

### 1.2 目标（已与产品确认）

| 决策项 | 结论 |
| --- | --- |
| 组织模型 | 保留团队与团长 |
| 任务与场景 | 一任务一场景；场景名称自由填写，录入时带标签字典补全引导；全新场景自动加入标签字典并生成新版本 |
| 任务要求 | 管理员自由填写 → 过一层 AI 规范化为标准提示词 → 管理员确认后生效 |
| AI 质检体系 | 重新构建；保留具身专属维度（第一人称/手部），任务要求作为「任务符合度」维度参与打分并影响总分与通过线 |
| 结算 | 按任务定价（每分钟积分）+ 质量系数档位，保持周期锁定、留痕、可调整 |
| 提交约束 | 任务可暂停/关闭，关闭后不可再提交；不设截止时间、单人上限、定向投放 |
| 在途数据 | 任务暂停/关闭只阻止新提交，已提交数据继续媒体解析、AI 质检和结算 |
| 场景字典 | 新场景自动入字典并生成新标签版本；动作/对象分类继续由模型输出用于库存统计；管理员可停用错录场景 |

## 2. 核心概念与数据模型

### 2.1 采集任务（Collection Task）

新增实体 `collection_tasks`，字段设计：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | varchar(64) | `TASK-<uuid8>` |
| `title` | varchar(120) | 任务标题（面向数采人员展示） |
| `description` | text | 任务说明/采集指引（数采端任务卡片与详情展示） |
| `scene_name` | varchar(120) | 场景名称（管理员填写，支持字典补全） |
| `scene_label_id` | varchar(64) nullable | 关联标签字典中的场景标签 id；全新场景在发布时自动创建并回填 |
| `raw_requirements` | text | 管理员自由填写的要求原文 |
| `normalized_requirements` | jsonb nullable | AI 规范化后的结构化要求（见 3.3），管理员确认后保存 |
| `normalization_status` | varchar(24) | `pending / ready / failed`（AI 规范化状态） |
| `price_points_per_minute` | numeric | 任务单价（每分钟积分）；空则回退全局默认积分规则 |
| `status` | varchar(16) | `draft / published / paused / closed` |
| `revision` | int | 任务版本号；每次「编辑并发布」递增 |
| `created_by_account_id / name` | | 创建人 |
| `published_at / paused_at / closed_at` | timestamptz nullable | 生命周期时间戳 |
| `created_at / updated_at` | | 审计时间 |

**生命周期**：`draft → published ⇄ paused → closed`（closed 不可逆，仅管理员可操作）。

- `draft`：仅管理员可见，可编辑；AI 规范化可在此阶段执行/重试。
- `published`：数采人员可见、可选、可提交。
- `paused`：数采人员可见但不可提交（展示「已暂停」），已提交数据继续处理。
- `closed`：不可提交；任务从任务大厅下架或标记结束。

**版本与快照原则**：编辑已发布任务并重新发布会递增 `revision`。提交（submission）在创建时**锁定任务快照**（任务 id、revision、scene_name、normalized_requirements、price_points_per_minute），后续任务修改不影响已提交数据的质检与结算。

### 2.2 提交关联任务

`submissions` 表新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | varchar(64) nullable + 索引 | 所属任务；历史数据为 null（legacy） |
| `task_revision` | int nullable | 提交时锁定的任务版本 |
| `task_scene_name` | varchar(120) nullable | 快照：任务场景名 |
| `task_requirements_snapshot` | jsonb nullable | 快照：规范化要求（AI 质检使用） |
| `task_price_points_per_minute` | numeric nullable | 快照：任务单价（结算使用） |

**约束**：新建上传必须选择 `published` 状态的任务；后端创建上传任务时校验任务状态，暂停/关闭后拒绝新上传。

### 2.3 场景与标签字典

- 沿用现有 `label-set-version` 版本快照机制（`label_set_versions`）。
- 管理员在任务表单输入场景名称时，前端调用补全接口（从当前激活标签版本的场景标签中模糊匹配）。
- 全新场景在任务**首次发布**时自动追加到激活标签版本并生成新版本（复用现有「编辑标签生成新版本」流程），写入审计。
- 管理员可在「标签与规则」页查看、停用自动添加的场景（停用后新任务不可选择，历史提交不受影响）。
- 动作/对象两级分类继续由 AI 从字典中选择输出，用于库存稀缺度统计（D5）。

### 2.4 定价与结算模型

- **任务定价**：`price_points_per_minute`（每分钟积分），为空时回退全局积分规则的默认每分钟积分。
- **质量系数**：沿用全局积分规则的分数档位（系数带），按质检 `final_score` 映射。
- **积分公式**：
  `points = effective_minutes × price_points_per_minute × quality_ratio`
  - `effective_minutes` = 有效时长/60000（无效片段剔除规则不变）。
  - `quality_ratio` 来自分数档位（如 80+ → 1.0，70–79 → 0.85 …）。
- **周期锁定机制保留**：积分周期、周期明细快照、锁定、锁定后调整流水与审计、CSV 导出全部不变。
- 周期明细新增字段：`task_id / task_name / task_scene_name / price_points_per_minute`（快照），支持按任务维度汇总、筛选、导出。
- **历史提交（legacy）**：无任务，按全局默认单价结算，保持现有行为。

## 3. AI 质检体系重构

### 3.1 提示词组合结构

```
[通用提示词框架（系统级，版本化，管理员可编辑）]
  ├── 输出 JSON 结构约束（schema，含 task_compliance 区块）
  ├── 硬性否决规则（文件损坏 / 精确重复 / 隐私安全 / 与任务场景无关）
  ├── 证据与时间戳要求
  ├── 人工复核触发规则
  ├── 通用画质维度（清晰度/曝光/稳定性/连续性，技术指标优先）
  ├── 具身专属维度（第一人称视角 / 手部与操作对象完整度）
  ├── 库存分类（动作/对象从字典选择；场景由任务锁定）
  └── 有效时长 / 无效片段规则
+
[任务要求区块（每次提交锁定的规范化快照）]
  ├── 场景信息（scene_name + 场景描述）
  ├── 要求条目列表（hard / soft 标记）
  └── 任务定价/其他展示信息（仅参考，不参与判定）
```

### 3.2 通用框架的重新构建（替换原 video_qc_v1）

原五维体系重构为「通用维度 + 任务符合度」两层：

| 维度 | 内容 | 来源 |
| --- | --- | --- |
| D1 画质与帧质量 | 清晰度/曝光/稳定性/连续性 + 分辨率/FPS（技术指标优先） | 通用框架 |
| D2 第一人称与构图 | c_pov / c_angle / c_orientation / c_arm_entry | 通用框架（具身专属，保留） |
| D3 手部与操作对象完整度 | 完整度/贴边/尺度/遮挡/对象可见性 | 通用框架（具身专属，保留） |
| D4 任务符合度 | 场景匹配度 + 要求逐条符合度（hard 权重高于 soft） | **任务要求区块（规范化快照）** |
| D5 库存价值与独特性 | 场景稀缺系数 + 相似度（近似重复） | 通用框架 + 服务端上下文 |

- 原 D4「任务真实性/完整度」拆解：任务真实性、进度、完成度并入任务符合度（结合任务要求判断）；「空转/凑时长/虚假」作为硬性否决候选与无效片段规则保留在通用框架。
- **通过线**：沿用全局质量规则 `passThreshold`（可在后续迭代中支持任务级覆盖）。
- **硬性否决新增**：`SCENE_MISMATCH`（视频内容与任务声明场景明显不符，置信度高时直接否决，否则进人工复核）；`UNRELATED_CONTENT` 定义收紧为「与任务场景无关」。

### 3.3 任务要求规范化（新增服务）

- **输入**：管理员自由填写的要求原文（raw_requirements）+ 场景名称 + 任务说明。
- **处理**：调用文本模型（百炼文本模型，与视频模型区分）输出规范化 JSON：

```json
{
  "scene_description": "对任务场景的一段标准描述，供模型理解场景边界",
  "requirements": [
    { "type": "hard", "content": "必须出现双手操作过程", "rationale": "用于手部完整度判定" },
    { "type": "soft", "content": "光线充足，画面清晰", "rationale": "" }
  ],
  "quality_notes": ["其他影响评分或复核的说明"]
}
```

- **时机**：任务创建/编辑保存时异步执行，管理员在界面**预览规范化结果**，可编辑条目（增删改、hard/soft 切换），确认后任务才可发布。规范化失败可重试，任务保留 draft。
- **快照**：确认后的规范化要求存入任务；提交时复制到 `submissions.task_requirements_snapshot`，AI 质检只读快照。
- **版本锁定**：AI 质检结果记录仍锁定提示词版本、质量规则版本、标签版本；新增锁定「任务要求快照」（随 submission 存储，无需额外版本表）。

### 3.4 质检输出 schema 调整

在现有 `video_qc_v1` 输出结构基础上：

- `detectedTask` 语义调整：`scene_id` 优先校验与任务场景一致（不一致进入任务符合度扣分或 SCENE_MISMATCH 候选）；`standard_task_id / variant_id` 继续从字典选择。
- 新增 `task_compliance` 区块：

```json
"task_compliance": {
  "scene_match": { "matched": true, "confidence": 0.95, "note": "" },
  "items": [
    { "requirement": "必须出现双手操作过程", "type": "hard",
      "result": "met" | "partial" | "unmet", "confidence": 0.9, "evidence_timestamps_ms": [] }
  ],
  "compliance_ratio": 0.92,
  "review_required": false
}
```

- 服务端规则引擎复算：D4 分数由服务端按 `task_compliance` 计算（hard 未满足 ≥ 1 项或 compliance_ratio 低于阈值 → 触发人工复核），模型分数仅作参考，防止模型自评漂移。
- `video-quality-result` 表存储结构随 schema 升级（迁移脚本），历史结果保持原样只读。

## 4. 任务管理模块（管理员端）

### 4.1 新页面「任务管理」

- **列表**：状态筛选（草稿/已发布/已暂停/已关闭）、场景搜索、分页；卡片/表格展示标题、场景、单价、状态、提交数。
- **创建任务**（表单）：
  1. 基本信息：标题、说明、场景名称（补全引导）、要求自由文本、单价（每分钟积分，可留空回退全局）。
  2. 保存草稿后触发 AI 规范化 → 弹窗预览规范化结果（条目可编辑、hard/soft 可切换、可重新规范化）→ 确认。
  3. 发布：校验规范化状态为 ready → 发布（全新场景自动入字典并生成标签新版本）。
- **编辑**：草稿可任意编辑；已发布任务编辑后需重新规范化并确认，保存为新 revision，已提交数据不受影响。
- **操作**：暂停 / 恢复 / 关闭（关闭不可逆，需二次确认并写审计）。
- **统计**：任务维度提交数、质检通过率、已结算积分（后续迭代）。

### 4.2 审计

任务创建、编辑、规范化确认、发布、暂停、恢复、关闭、场景自动入字典均写入审计日志（复用 `AuditService`）。

## 5. 数采端流程改造

### 5.1 任务大厅（新页面）

- 展示所有 `published` 任务卡片：标题、场景、要求摘要（展开查看完整要求）、单价、状态。
- `paused` 任务展示但置灰「已暂停」；`closed` 任务不在大厅展示（或归入「已结束」）。
- 点击「去采集」进入上传页并携带任务上下文。

### 5.2 上传流程改造

1. 选择任务（必须，前端 + 后端双重校验任务状态）。
2. 阅读任务要求并确认（新增确认步骤，复用现有授权确认弹窗风格；后端创建上传任务时校验并要求 `taskRequirementsConfirmed=true`）。
3. 上传视频（MP4/MOV、分片、大小校验等**全部不变**）。
4. 上传后流程不变：媒体解析 → AI 质检（使用任务要求快照）→ 人工复核 → 结算。

### 5.3 我的数据 / 质检结果 / 详情

- 列表与详情增加「所属任务 / 场景」展示与筛选。
- 质检详情展示任务符合度结果（D4 得分、逐条要求判定）。

### 5.4 团长端

- 团队数据页增加按任务筛选；团队分析场景分布改为按任务/场景聚合（小改）。

## 6. 结算调整

- 积分周期生成逻辑读取提交快照 `task_price_points_per_minute`（无任务回退全局默认），`pointsPerMinute` 存快照。
- 周期明细 CSV 导出增加任务列。
- 周期锁定、锁定后调整流水、审计不变。
- 管理员结算页增加按任务汇总视图（每任务：提交数、有效时长、积分、单价）。

---

## 7. 迁移与兼容策略

- 新增表 `collection_tasks`；`submissions` 加可空任务列（索引 `task_id`）；`point_cycle_items` 加任务快照列。
- 历史提交：`task_id = null`，AI 质检使用「无任务模式」（通用框架，无任务要求区块，D4 退化为原「任务真实性/完成度」通用判定），结算按全局默认单价。
- 新提交强制要求任务，前端上传入口必须经任务大厅。
- 质检 schema 升级通过迁移创建新版本输出结构；`video-quality-result` 历史行保持旧结构只读，详情页兼容两种结构。

## 9. 风险与待确认项

1. **规范化质量**：自由文本要求 → 规范化条目的准确性直接影响 D4；管理员确认环节可兜底，后续可引入示例/模板引导。
2. **新场景自动入字典**：错录场景会产生噪声标签，靠管理员停用兜底；建议限制为「发布时自动创建」而非「输入时即创建」。
3. **D4 权重与通过线**：任务符合度占总分权重、hard 未满足是否直接否决，需要上线后根据实际质检分布调优（先固定默认值，后续做成可配置）。
4. **文本模型依赖**：规范化需要额外调用百炼文本模型，需确认 `QWEN_BASE_URL` 是否提供文本模型端点与独立 API Key 计费。
5. **任务维度统计**：任务提交数/通过率/积分汇总依赖新查询，工作量小但需排期。
6. **提交数量无上限**：未设单人上限，存在刷量风险；依赖质检硬性否决与近似重复机制控制，后续可按需补充频率限制。
